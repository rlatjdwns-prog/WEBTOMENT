# 그 보도, 정정이 필요합니다 — 배포 가이드

## 구성
- `index.html` — 정적 프런트엔드 (Vercel + GitHub로 배포)
- `apps-script/Code.gs` — 백엔드 (구글 스프레드시트 + Apps Script 웹 앱)

데이터는 전부 구글 스프레드시트에 저장됩니다:
- **참가자** 탭 — 이름/연락처/주소/동의 여부 (스크립트가 자동 생성)
- **사례** 탭 — 토너먼트에 쓰일 왜곡 사례 (직접 입력)
- **통계** 탭 — 누적 투표 결과 (스크립트가 자동 관리)

---

## 1단계 — 구글 스프레드시트 + Apps Script 설정

1. 구글 드라이브에서 새 스프레드시트를 만든다.
2. 첫 번째 탭 이름을 **사례** 로 바꾸고, 1행에 아래 헤더를 그대로 입력한다.

   | id | outlet | title | quote | description | sourceUrl |
   |----|--------|-------|-------|-------------|-----------|

   2행부터 실제 왜곡 사례를 한 줄씩 채운다. `id`는 `c1`, `c2`처럼 서로 겹치지 않게만 하면 된다.
   예시 한 줄:
   `c1 | OO일보 | '조현병 전과자' 표현으로 범죄 보도 | 조현병 병력이 있는 30대 남성이 또... | 질환명과 범죄를 인과관계처럼 나열해... | https://...`

3. 상단 메뉴 **확장 프로그램 > Apps Script** 클릭.
4. 기본 생성된 `Code.gs` 내용을 지우고, 이 폴더의 `apps-script/Code.gs` 내용을 그대로 붙여넣는다.
5. 저장(Ctrl/Cmd+S) 후, 우측 상단 **배포 > 새 배포**.
6. 유형에서 **웹 앱** 선택 →
   - 실행 계정: **나(본인 이메일)**
   - 액세스 권한: **전체 허용(익명 포함)**
7. 배포 후 나오는 **웹 앱 URL**(`.../exec`로 끝남)을 복사해 둔다. 이후에도 계속 이 URL을 쓴다.
8. 처음 실행 시 구글이 "승인되지 않은 앱" 경고를 띄울 수 있는데, 본인 계정이므로 **고급 > 이동(안전하지 않음)**을 눌러 승인하면 된다.

> **참가자·통계 탭은 처음엔 안 보여도 정상입니다.** 첫 참여자가 등록되거나 첫 투표가 발생하는 순간 스크립트가 자동으로 만듭니다.

## 2단계 — index.html에 웹 앱 URL 연결

`index.html`을 열어 아래 줄을 찾아서

```js
const GAS_URL = "https://script.google.com/macros/s/여기에_배포_ID를_넣으세요/exec";
```

1단계에서 복사한 실제 웹 앱 URL로 교체한다.

## 3단계 — GitHub에 올리기

터미널에서 이 폴더 기준으로:

```bash
git init
git add .
git commit -m "미디어 왜곡 토너먼트 캠페인"
git branch -M main
git remote add origin https://github.com/<본인계정>/<저장소이름>.git
git push -u origin main
```

(GitHub에 새 저장소를 먼저 만들어 둔 뒤 위 명령을 실행하면 됩니다.)

---

## 4단계 — Vercel로 배포

1. https://vercel.com 에 GitHub 계정으로 로그인.
2. **Add New > Project** → 방금 만든 저장소 선택.
3. 별도 빌드 설정 없이(정적 HTML이라 Framework Preset은 **Other**로 두면 됨) **Deploy** 클릭.
4. 배포가 끝나면 `https://<프로젝트명>.vercel.app` 주소가 생성됩니다. 이 주소가 실제 캠페인 참여 링크입니다.

이후 `index.html`이나 `Code.gs`를 수정하고 GitHub에 push하면 Vercel이 자동으로 재배포합니다. **사례 추가/수정은 코드 수정 없이 구글시트의 "사례" 탭에서 바로 하면 됩니다.**

## 확인해야 할 것

- **개인정보 동의 문구**: `index.html`의 `#view-consent` 안 동의 문구는 초안 예시입니다. 실제 배포 전 기관의 개인정보처리방침 담당자 검토를 받아 정식 문구(보유기간, 파기 절차, 위탁 여부 등)로 교체해 주세요.
- **접근 범위**: Apps Script를 "전체 허용"으로 배포하면 URL을 아는 누구나 데이터를 읽고 쓸 수 있습니다(참가자 정보 열람은 스프레드시트 자체 공유 권한으로 보호되니, 스프레드시트는 본인만 접근 가능하게 유지하세요).
- **투표 응답 확인 안 함**: 투표(`sendVote`)는 응답을 기다리지 않고 바로 보내는 방식이라 네트워크 오류 시 조용히 실패할 수 있습니다. 참여자 수가 매우 많아지면 재시도 로직을 추가하는 것도 고려해볼 만합니다.
