# 그 보도, 정정이 필요합니다 — 배포 가이드

기사 원문을 그대로 보여주고, 참여자가 편견을 부추기는 표현을 직접 클릭해서 찾는 "틀린그림찾기"형 캠페인입니다.
기사 추가/수정/삭제는 구글시트가 아니라 **웹사이트 우측 하단의 관리자 화면**에서 합니다.

## 구성
- `index.html` — 정적 프런트엔드 (Vercel + GitHub로 배포)
- `apps-script/Code.gs` — 백엔드 (구글 스프레드시트 + Apps Script 웹 앱)

데이터는 전부 구글 스프레드시트에 저장됩니다:
- **참가자** 탭 — 이름/연락처/주소/동의 여부 (자동 생성)
- **사례** 탭 — 게임에 쓰일 기사 (관리자 화면에서 자동으로 채워짐)
- **통계** 탭 — 기사별 발견율/오답 수 누적 (자동 생성)
- **추첨** 탭 — 전화번호별 당첨 여부 (자동 생성)
- **설정** 탭 — 당첨 인원수·확률 (자동 생성, 시트에서 직접 수정하거나 관리자 화면에서 수정)

---

## 1단계 — 구글 스프레드시트 + Apps Script 설정

1. 구글 드라이브에서 새 스프레드시트를 만든다. (탭은 미리 만들 필요 없음 — 전부 자동 생성됨)
2. 상단 메뉴 **확장 프로그램 > Apps Script** 클릭.
3. 기본 생성된 `Code.gs` 내용을 지우고, 이 폴더의 `apps-script/Code.gs` 내용을 그대로 붙여넣는다.
4. **관리자 비밀번호 설정 (중요):**
   - 좌측 톱니바퀴(프로젝트 설정) 클릭 → 아래로 스크롤 → **스크립트 속성** → **속성 추가**
   - 속성: `ADMIN_TOKEN` / 값: 원하는 비밀번호 (예: 팀에서만 아는 문구)
   - 이 비밀번호는 코드나 웹사이트 어디에도 노출되지 않고, 서버(Apps Script)에서만 대조됩니다.
5. 저장(Ctrl/Cmd+S) 후, 우측 상단 **배포 > 새 배포**.
6. 유형에서 **웹 앱** 선택 →
   - 실행 계정: **나(본인 이메일)**
   - 액세스 권한: **전체 허용(익명 포함)**
7. 배포 후 나오는 **웹 앱 URL**(`.../exec`로 끝남)을 복사해 둔다.
8. 처음 실행 시 구글이 "승인되지 않은 앱" 경고를 띄울 수 있는데, 본인 계정이므로 **고급 > 이동(안전하지 않음)**을 눌러 승인하면 된다.

Code.gs를 나중에 수정하는 경우, 스크립트 편집기에서 **배포 > 배포 관리 > 기존 배포 수정(연필 아이콘) > 새 버전으로 배포**를 해야 반영됩니다 (URL은 그대로 유지됨).

## 2단계 — index.html에 웹 앱 URL 연결

`index.html`을 열어 아래 줄을 찾아서

```js
const GAS_URL = "https://script.google.com/macros/s/여기에_배포_ID를_넣으세요/exec";
```

1단계에서 복사한 실제 웹 앱 URL로 교체한다.

## 4단계 — Vercel로 배포

1. https://vercel.com 에 GitHub 계정으로 로그인.
2. **Add New > Project** → 방금 만든 저장소 선택.
3. Framework Preset은 **Other**로 두고 별도 빌드 설정 없이 **Deploy** 클릭.
4. 배포가 끝나면 `https://<프로젝트명>.vercel.app` 주소가 생성됩니다.

---

## 5단계 — 관리자 화면에서 기사 등록

1. 배포된 사이트 접속 → **우측 하단 톱니바퀴(⚙)** 클릭 → 1단계에서 설정한 비밀번호 입력.
2. **헤드라인**, **본문**을 입력한다. 본문은 줄바꿈으로 문단을 구분한다.
3. 문제되는 표현을 마우스로 드래그해서 선택한 뒤 **"선택 영역을 문제 표현으로 표시"** 버튼을 누르면, 설명을 물어보는 창이 뜬다. 설명을 입력하면 자동으로 `[[문구|설명]]` 형식으로 감싸진다.
4. 한 기사에 문제 지점은 여러 개 표시해도 된다.
5. **기사 추가**를 누르면 바로 반영된다. 목록에서 **수정 / 삭제**도 같은 화면에서 가능하다.

---

## 6단계 — 즉석 당첨 추첨

참여자가 모든 기사를 다 풀면(세션 종료 시점) 자동으로 추첨이 이루어지고, 그 자리에서 바로 당첨 여부를 보여줍니다.

- 총 당첨 인원수와 당첨 확률은 스프레드시트의 **설정** 탭에서 관리됩니다 (`MAX_WINNERS`, `WIN_PROBABILITY` 두 행). 시트 셀 값을 직접 고쳐도 되고, 웹사이트 관리자 화면(⚙ → "당첨 추첨 설정")에서 숫자를 입력하고 저장해도 됩니다 — 어느 쪽으로 바꾸든 결국 이 시트 한 곳에 반영되니 값이 두 군데서 따로 노는 일은 없습니다.
- 당첨자가 설정된 인원수만큼 채워지면 그 이후 참여자는 자동으로 "다음 기회에"로 처리됩니다.
- 전화번호를 기준으로 한 사람은 한 번만 추첨 대상이 되며, 같은 번호로 다시 참여해도 처음 결과만 다시 보여줄 뿐 재추첨되지 않습니다.
- 동시에 여러 명이 동시에 완료해도 서버에서 순서대로 처리(잠금)하기 때문에 당첨자가 설정 인원보다 많이 나오는 일은 없습니다.
- 당첨 현황은 스프레드시트의 **추첨** 탭에서 실시간으로 확인할 수 있습니다 (전화번호 / Y·N / 일시).

**참고**: 이 방식은 "완료 즉시 결과 확인"과 "정확히 N명"을 동시에 만족시키기 위한 확률 기반 즉석 추첨입니다. 예상보다 참여자가 적으면 설정 인원이 다 채워지지 않을 수도 있고, 반대로 초반에 당첨 확률이 높게 몰릴 수도 있습니다. 예상 참여 규모에 맞춰 확률을 조정해 보세요 (참여자가 많을수록 확률은 낮게, 적을수록 높게).

## 확인해야 할 것

- **개인정보 동의 문구**: `index.html`의 `#view-consent` 안 동의 문구는 초안 예시입니다. 실제 배포 전 기관의 개인정보처리방침 담당자 검토를 받아 정식 문구로 교체해 주세요.
- **관리자 비밀번호 관리**: `ADMIN_TOKEN`을 아는 사람만 기사를 수정할 수 있습니다. 비밀번호가 유출되면 스크립트 속성에서 값을 바꾸고 다시 배포하면 즉시 무효화됩니다.
- **읽기 데이터는 공개**: 기사 데이터(`?action=data`)는 게임 진행을 위해 누구나 읽을 수 있어야 하므로 공개되어 있습니다. 참가자 개인정보(이름/연락처/주소)는 쓰기 전용 API로만 접근 가능하고, 조회 기능이 없어 URL을 안다고 해도 읽을 수 없습니다. 스프레드시트 자체는 본인만 접근 가능하게 공유 설정을 유지하세요.
